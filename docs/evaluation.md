# 评测与 Elo v1

协议：ra-arena-full-info-v1。使用 Rust 重写引擎的完整世界观测和合成场景；首期场景池 duel-v1、economy-v1。双方科技、资金、命令预算和 tick 上限一致。每个镜像双局使用同一 seed，第二局交换出生位；双方先观察同一 tick 再入队命令。

维护者本地评测；仓库 CI 不执行 Agent、不跑游戏。超时及双方同时淘汰记和局；panic、崩溃、回放失败、环境错误使双局无效，不伪造为胜负或平局。保留对应错误记录用于排查，但不纳入有效流水。

一个赛季固定引擎源码提交（干净工作区）、规则 SHA-256、场景池 SHA-256、tick 上限、命令上限、观测协议与 Elo 参数。新增 Agent 版本从 1500 分开始，旧版本保留；改策略不继承旧版分数。引擎、规则或协议变化另开赛季。只有同一赛季的结果可累计，不与引擎单次循环赛的临时分直接拼接。

每对镜像比赛只更新一次：E(A)=1/(1+10^((R(B)-R(A))/400))；S(A)=(s1+s2)/2（均以 A 视角，胜1/和0.5/负0）；delta=32*(S(A)-E(A))；A 加 delta、B 减 delta。同分连胜两局 +16；一胜一负不变。中间不舍入，仅展示保留两位小数。

按批次 sequence 升序、批次内 pairs 数组顺序结算；不按 played_at 重新排序。同一双局 ID、相同场景/种子/双方身份的重复结果均拒绝，防止重复计分。保留总体榜、各场景独立 Elo、胜和负、单局数和得分率；少于20单局标记暂定。

每条结果固定 Agent registry_commit 与 checksums_sha256（通过赛季名单），保存两局 seed/出生位/胜负/结束原因/终局哈希，以及原始报告 URL 和 SHA-256。哈希保证内容可核对，不证明比赛本身真实；真实性由维护者的测试和证据负责。

leaderboard 保存归一化人工录入格式，尚未实现 ra-arena 报告自动导入。不要直接复制原始引擎报告中的汇总 Elo；从逐局结果录入后统一重算。
